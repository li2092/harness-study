一次委派的生命周期：四张欠条钉在同一条时间线上

父 run 派出两个分身，一个顺利、一个出岔——第十一章留下的四张欠条，各自落在这条线的哪一刻，看一遍就清楚。底部那条红带是破坏实验的四个场景：它们打的正是四张欠条的位置。

读写不对称

并行地读可以扩展，并行地写会制造互相冲突的决策——所以收敛那一步必须落回单点。厂商自评数据：检索型任务上多 agent 比单 Opus 高 90.2%，代价是 token 约为单 agent 的 3.75 倍，且 token 用量本身解释了 80% 的表现差异（12.3）。

父的账单

父要为每个 child 承担一份完整的生命周期照管：起得来、管得住、收得回、验得了。child 越多，父越重——这是"能不上多 agent 就别上"的第一条理由（12.1）。慢 subagent 阻塞整批，就是父的照管缺了"收得回"那一角。

最容易缺的一条记录

拒绝往往留痕，采信常被当默认而无声——"回传被采信"那一刻的校验记录，是本章 L2 底线里最容易缺的一条。查不到它，"这个结果哪个分身出的、谁核过"事后无从回答。
