八张组件卡：守什么约、起步几级、什么时候搬家

谁连谁在第一章 1.4 的拓扑里已经画完，这张图不重画数据流。它给的是卡面属性——每个组件主守哪份契约、L 级起步定在哪、单机基线选了什么、以及负载长大时从哪一刀切出去。完整六栏住工作制品 G（Component Register）。
真相三件 · 谁持有、谁记录、谁归档
L2
状态层
持久真相唯一落点，答"现在是什么"
真相契约——单写者串行化并发写；持久对象带 owner 与 version
单机基线：SQLite 单写者（换掉一类并发问题，上限是吞吐）
✂ 多实例或出现多写者 → Postgres ＋ lease
L2
事件流
发生过什么的机器可读记录
转移契约——只追加，永不改写
单机基线：append-only 表，不上队列（保住单机运维的简单与"一条 SQL 对完账"）
✂ 订阅方跨了机器 → 进程内分发换事件总线
L2
证据存储
归档 trajectory / policy 决策 / verifier 结论 / artifact 来历
证据契约——只存不判
单机基线：与事件流分储（不把高频小事件与低频大归档压进同一张表）
✂ 判断动作归第十三章证据面，不在这张卡上
执行两件 · 谁裁决、谁干活
L2
run manager
单执行内核：准入、同会话互斥、policy 与 limit 裁决、孤儿 run 收尾
转移＋权限契约的裁决点，并承交互契约的收敛义务
边界两头划清：不碰模型不碰工具，也不长业务逻辑——只裁"能不能跑"，不管"跑什么"
✂ 单例撑不住 → 互斥从进程内换分布式锁 / lease
L1
agent loop
一轮任务的编排者：组装 context、调模型、执行工具、循环到终答
不单独主守哪份契约——它是全部契约的履约现场
因此领全卷最硬的约束：内存即易失，攒的一切要么立刻落盘，要么等于不存在。九步动线里零落盘点归它
单机基线：手写同步循环，不上 graph 引擎
外界三件 · 朝用户、朝模型、朝世界
L1
入口层
UI / API / IM / scheduler——适配意图、转发流
交互契约的呈现半边
投影不回写；不实现任何 permission、cancel 捷径——四种语义只在内核
把界面做厚一直有诱惑，代价是引回一份"第二真相"
L2
model adapter
朝着模型，是调用的记账员
转移＋证据契约在模型调用上的那几格
每次调用完整留档，恢复时复用记录、永不重调。不做 routing 裁决（归 run manager），也不解释输出（归 loop）
单机基线：库内 adapter，不抽网关
L2
tool executor
朝着外部世界，是副作用的唯一大门
副作用契约
顺序定死：先落盘意图 → 执行 → 落盘结果；工具返回只算一面之词。policy 判定不在这张卡上，它只执行裁决结果
✂ 要隔离出去 → 子进程沙箱换 worker queue

L 级起步：六张 L2、两张 L1

本章不给自己评级——L 尺量的是机制，本章交付的是图。第六栏写的是每个未来机制的起步预期，当作第五到十三章的验收底线预告。带 ✂ 的四条是取舍栏里的迁移信号，不带的两张不设断口，这个不对称本身是信息。

组件边界即迁移断口

负载长大时逻辑架构不动，换的只是放法。八件先住同一个进程边界内——逻辑图即物理图；四个切换信号各对应一条边界，到了再切。
