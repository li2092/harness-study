run 的七个状态：卡在 running 不是状态，是缺陷

每个状态都是被一种处境逼出来的，每条转移都由「触发事件 ＋ guard ＋ 目标状态 ＋ terminal reason」四要素定义。这张图给形状，转移表给条文。
转移表节选 · 全表十七行住工作制品 H（Run 状态转移表）
#触发事件guard（什么前提必须先成立）目标 / terminal reason
1内核派发同会话无活跃 run 且额度足够running
2需要审批或追问—waiting
3输入到达授权仍有效（需重验）running
4任务做完—completed
5新意图触发抢占旧 run 半轮内容已终态化落盘cancelled（preempted）
6执行出错—failed（业务失败）
7启动扫描发现进程不在进程标识已消失interrupted
8恢复裁决续跑版本兼容且 checkpoint 完整queued
9恢复裁决放弃版本不兼容或 checkpoint 残缺failed（unrecoverable）
停留上限与超时归宿
queued排队超时 → cancelled（queue_expired）
running心跳超时 → 看门狗按基础设施失败收尾
waiting自带 deadline，过期是显式终态
interrupted由恢复裁决送往续跑或终态（第七章）
两条扫描路径，别混
看门狗进程还在、run 卡死 → 直接给终态
启动扫描进程没了、可能有救 → 收敛 interrupted，交恢复裁决
一条铁律压轴：终态之间不许互转——completed 改成 failed 等于改写历史。判错了就追加一条更正记录指向原状态，历史本身不动。代码里改 run.status 的路径只许有一条：内核的 transition 函数，查表、验 guard、写状态、落一条 run.* 事件。
