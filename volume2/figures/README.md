# 第二卷配图

出图工单见 [`PLAN.md`](./PLAN.md)（Tier 1 十六张 / Tier 2 十三张、跨章分工、图文一致性纠错、待裁决项）。

## 出一张图

```bash
# 1. 复制一张同图型的现成图当骨架
cp t1-flow-5.2-run-states.html t1-<型>-<节>-<slug>.html
# 2. 改内容（信息点须对得上 PLAN 里登记的行号）
# 3. 渲染
~/.venvs/docgen/bin/python _render.py t1-<型>-<节>-<slug>.html t1-<型>-<节>-<slug>.png
```

`_render.py` 走系统 Chrome，3x DPI，截 `.canvas` 元素。**依赖 `~/.venvs/docgen/bin/python`**（带 playwright），不要用系统 python3。

## 命名

`t<层>-<图型>-<节号>-<slug>`。层＝ `t1` Tier 1 / `t2` Tier 2；图型取 PLAN 的九种之一（`matrix` `flow` `sequence` `layered` `cardgrid` `comparison` `timeline` `tree` `analogy`）。附录图没有节号，`<节号>` 位置写 `appendix`。

## 视觉

`_base.css` 是 jimi-ink 公共底（暖石底 `#f4f0eb` ／ 淡紫网格 ／ 紫 `#6d28d9`），**与正文 PDF 同一套色板**。字体走 `../pdf-build/fonts/` 本地 OFL 文件，不依赖 CDN。

画布固定 1320px 宽。每张图自带 `<style>` 写自己的布局，`_base.css` 只管外壳（canvas／grid-bg／label-type／h1／sub／rule／foot）。

## 硬约束

- **成品有效宽度上限 182mm**（A4 版心）。超宽会触发 Chromium 打印缩放、把整本书等比缩小——第二卷已因宽表踩过一次（正文 14pt 被渲成 9.3pt）。按 1320px 画布出图，印刷宽定 182mm，高度换算：`高(mm) = 图高px / 图宽px × 182`。

- **画布 px → 印刷 pt 的换算是 ×0.391**（1320px 铺满 182mm）。所以图里 16px 的字，印出来只有 6.3pt——比正文 14pt 小一半还多。**图内最小字号不低于 16px**（≈6.3pt），核心标签给到 26px（≈10pt）。入门卷的基准是卡片正文约 14.8px ≈ 5.8pt，可以对标但不要更小。

- **图要扁，不要方**。入门卷的图宽高比约 2:1，一屏只放一个 archetype，所以每个元素在纸上够大。第一版 5.2 做成 1:1、塞了状态机加两张图例表，印出来图例只有 5pt——重做后砍掉图例表、宽高比收到 1.33:1，最小字回到 6.4pt。**判据：单张图承载一个 archetype，不叠加。**

- **不要把正文已有的表搬进图**。5.2 第一版的两张图例表，一张就在图的正上方（5.2 停留上限表）、一张在下一页（5.3 转移表节选）——既挤小了图，又违反 PLAN 里「表已经是图的不再画」。图只画正文没有的那一层（形状、方向、时序）。
- **信息忠于原文**。每个信息点要能在正文指出行号，见 PLAN 各条的"信息点"。图文不符是入门卷上一版翻车的原因。
- **脱敏**：三个匿名系统是三个不同项目，不得混为一谈——配套实现项目（Rust harness）／桌面案例项目（TypeScript 桌面 agent）／配套中继服务（TS relay）。公开产品照实具名。

## 接进正文

正文写图片 ＋ 紧跟一行斜体图注，`pdf-build/make_book.py` 自动升级为带编号的 figure 并生成图目录页：

```markdown
![](figures/t1-flow-5.2-run-states.png)

*图 5.2 · run 的七个状态：卡在 running 不是状态，是缺陷*
```

编号规则 `图 <章>.<节>`（编号取图的**主场节**，不是它落在哪一段）；附录图用 `图 附.1`。图接进正文后，同步删掉该处的 `（配图占位：…）`，并把这一行补进 `99-appendix.md` 第五节图表清单。

`make_book.py` 的 `FIG_RE` 图号组是 `[^\s·]+`（2026-07-26 由 `[\d.]+` 放宽，否则"附.1"这类非纯数字编号进不了图目录）。

**落位两条规矩**（10.3、15.3 两张踩出来的；2026-07-26 全量亲审后又按此规矩后移了 3.4／5.2／6.0／7.10／8.2／12.2 六张）：

- **编号挂主场节，位置放到材料齐了之后**。13.2 的图落在 13.3 末、10.3 的图落在 10.4 末、15.3 的图落在 15.4 末——都因为图里出现的名词（四条纪律、产出物）要等后一节才讲完。图提前上，读者只能冷读图例；图号跟着主场节走，索引才不乱。
- **图的底注不许抢章节结尾**。15.3 初稿底注用了 15.6 的收束句，等于在正文讲到之前把全卷最后一句剧透了；改成 15.1 的代价句。凡是落在末章、末节的图，底注先查一遍下文还有没有更重的话没说。便签卡同理：15.2 的便签曾整句引 15.6 收束句、9.1 的便签曾整句引 9.5 收束句，亲审时都撤了。

**SVG 文本里不许用 HTML 标签**（7.1 那张踩出来的）：`<text>` 里写 `<b>` 会让 HTML 解析器当场跳出 SVG 外来内容模式——之后的所有元素全部按普通 HTML 渲染，图从那一点直接断掉，而 linter 只看得见断点之前的半张图（照样报绿）。加粗一律用 `<tspan font-weight="700">`。同族陷阱：纯 HTML 表格图没有 `<svg>`，linter 五项检查全部空转，必须目视。
