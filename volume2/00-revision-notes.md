# 修订记录

本卷 2026 年 9 月修订。读过 0728 版的读者，可以从这一章了解改了哪里。

## 修订范围与原则

这次修订对照一手资料核查了书中引用的外部事实，统一了三卷的术语，修正了几处论证与事实不符或前后矛盾的地方，并按"让第一次读的人也读得懂"的标准重写了部分段落。书的观点、结构、六份契约与八个组件的框架都没有变。

各章文末的"审稿日志""引用来源"与章首版本注属于编辑工作区，这次没有改动。三卷共用的术语约定与外部事实的核查结论，见仓库根目录的 [`术语对照表.md`](../术语对照表.md)。

## 事实更正

| 位置 | 旧版说法 | 修订后 |
|---|---|---|
| 1.1 | 命中大模型缓存时输出相同的概率更高，开发时常在请求头加随机串避免命中 | 删去。前缀缓存只复用前缀的计算，不改变输出；输出不确定的来源是采样随机性、服务端批处理导致的浮点累加顺序变化，以及模型版本更新 |
| 1.3 | 四问"正是控制论四原则"，出自 Wiener 1948；"反馈环的最小完备分解" | 可观测性、可控性出自 Kalman 1960 年前后的状态空间理论；"四原则"与"四问"是本书的组织方式，未证明完备 |
| 1.4 | 以数据库 WAL 为"历史靠改不了才可信"的例子 | WAL 会被 checkpoint 截断，不是只追加的历史；改用会计账簿的冲正分录与事件日志作例子 |
| 1.3、2.7、3.7、12.1 | MAST 的某一类失效"正是"本卷某类违约的统计画像 | 改为"方向一致，可以互相印证"，注明 MAST 各类的原义（多 agent 系统的失效分类）与所引占比的版本（v3，2025-10） |
| 2.6 | 96% 的缓存命中意味着 N 次复跑统计上等于 1 次 | 不成立：agent 每轮重发全部历史，命中主要来自同一 run 内的后续轮次；前缀缓存命中不改变输出（DeepSeek、OpenAI 官方文档）。复跑不独立的真正来源见入门卷反模式 AP01 |
| 2.6 | 同时动两个机制，"数学上无从归因" | 只跑全开和全关两组时无法归因；要么一次只动一个，要么做析因设计 |
| 3.9 | 若用 Temporal，缺口二、缺口三"根本不成立" | 缺口三不成立；缺口二只能部分缓解：单个 activity 内的流式半截输出不进 event history，运行中的状态也需另写 Query |
| 4.3、7.2 | 模型调用"恢复时复用记录、永不重调" | 已完成并已记录的调用复用；崩溃时正在进行、结果未记录的调用只能重发（与 Temporal 对未完成 activity 的重试语义一致） |
| 5.7 | fencing 这个名字出自 Kleppmann | Kleppmann 2016 年的博文与《数据密集型应用系统设计》是经典阐述；更早的 Chubby（2006）称之为 sequencer |
| 5.7 | 并发原语"先上乐观并发，冲突率撑不住再上租约" | 按临界区性质选择：短小、冲突少的用乐观并发；跨进程长时间持有的用租约，并配围栏令牌 |
| 5.8 | 很少被测试的恢复代码"真崩溃时必然出问题" | 改为"更容易出问题"（Candea & Fox 2003 的原意） |
| 6.0 | 顺序以数据库自增序号为准 | 只在单写者下成立；多写者时先拿序号的事务可能后提交，留到第三卷处理 |
| 6.1 | 把"当前态一概不存"的纯粹事件溯源作为一端 | 事件溯源本身就允许快照与读模型，外部副作用也不靠重放重建；改为直接写本卷的做法 |
| 第六章、7.10 | 恢复时"按最后完整行截断" | 有事务保护的 SQLite 没有写了一半的行；恢复从最后一个已提交的位置开始 |
| 7.4 | Temporal 的时钟与随机数接口把结果写进 event history | workflow.now 取历史中 workflow task 的开始时间，random 确定性播种，都不单独写记录；只有 SideEffect 把值作为 marker 写进历史 |
| 9.3 | 以 MCP 规范拟移除会话 ID 佐证续传不能依赖会话 | 主论证改为"会话 id 表达不了收到第几条事件，续传需要事件级游标"；MCP 2026-07-28 版已按 SEP-2567 移除 `Mcp-Session-Id`，作为另一层协议的旁证 |
| 10.8 | Temporal 处理代码改版"只对新启动的执行生效" | 该类比说反了：运行中的执行首次走到补丁点就会走新分支。已删去类比，结论改用本章自己的理由支撑 |
| 10.2 | "业界把它细分成四种手段" | 出自 Anthropic 2025-09 的 context engineering 文章；两个百分比来自不同评测，分开注明 |
| 11.2 | "Anthropic 的权限体系有一个六步求值序"；"hook 是软的" | 六步顺序出自 Claude Agent SDK：Hooks → Deny → Ask → Permission mode → Allow → canUseTool；Claude Code 规则层为 deny → ask → allow。hook 的强制点在模型之外，但失败语义是放行，可作拦截手段，不能作安全边界 |
| 11.5 | 共因失效（common-mode failure） | 英文改为 common-cause failure（CCF）；共模失效另指以同一种模式失效 |
| 12.3 | "token 用量解释了 80% 的表现差异"；多 agent 约为单 agent 的 3.75 倍 | 80% 注明出自 Anthropic 多智能体研究系统文章在 BrowseComp 上的分析；3.75 倍注明是两个粗略倍数相除，只作量级参考 |
| 12.4 | 以两个 agent 互改配置的演示"坐实"委派取并集的危险；每次委派都成了 confused deputy | 该演示是平级 agent 横向提权，不是父子委派，按原意描述；confused deputy 按标准含义写 |
| 13.4 | 永不 UPDATE 换来"不可抵赖" | 改为"历史不被应用层覆写"；防篡改需要哈希链或 WORM 存储 |
| 1.3 | 从 L1 升到 L2 的工作量约为做到 L1 的五分之一；hook 机制"有名字两个月" | 五分之一没有测量依据，改为按生产代码行数粗算的实例：只补后端事件约为机制本身的三到四成，连界面展示一起做与机制本身相当；时长更正为一个多月 |
| 3.3 | 增量持久化"按事件节流 upsert"；run 开始即写入 pending 态的用户消息；中断后"顶多缺最后一个节流间隔" | 按实现改为每 2 秒把已完成步骤的快照更新进预写的 assistant 占位行；处于 pending 态的是占位行；中断后顶多缺正在生成的那一步外加最近两秒 |
| 5.8 | 看门狗 deadline 未给取值 | 补取值原则：大于单步最长合法耗时，让操作级超时先触发；静默思考的模型单独放宽，附中继空闲阈值误杀的一次实例 |
| 11.2–11.4、破坏实验 | hook fail-open、skill 作用域、"只读"工具藏外发三个缺口归在"配套中继服务" | 这三处代码在桌面案例项目，归属更正；隐私映射表属于请求间隔离，不再算作场景 3 的近似案例 |
| 11.4 | 密钥隔离"暂无一手素材" | 补上配套中继服务代持上游密钥、客户端只持可吊销令牌的一手做法，附反例测试 |
| 第十二章交付物 | 列有"多 agent 编排模式对照"正文表 | 该表从未写出，交付物改为"双层控制流与何时上多 agent 的判据" |

## 结论与建议有变化的地方

- **八个组件是否"最低"**（1.4、4.2 与第四章的破坏实验）：旧版称八是"单机的最低充分解"，但 4.2 自己承认证据存储可以与事件流合并。修订后改为"八份职责缺一不可"，单机基线把它们实现为八个组件，职责与组件不必一一对应；破坏实验的判定相应改为"职责必要性"。
- **抢占的状态转移**（5.5、5.12、工作制品 H）：旧版把抢占写成一条"原子转移"。修订后分两步：先发 abort 并等旧 run 落盘，这期间仍记为 running、事件中标 cancel_requested；落盘后再执行 running→cancelled，guard 检查"半轮已落盘"。preempted 按新意图的发起者归类，用户发起归用户取消，scheduler、webhook 等无人值守入口归策略拒绝。
- **恢复时 prompt 取哪一版**（10.8）：结论不变（塑形内容按崩溃前版本，系统约束取当前版），论据改为：同一 run 前后行为需一致、调用留档可复用；约束收紧必须立即生效。
- **构造顺序**（14.2）：旧版主张"每一步只依赖已就绪的契约"，但示范步骤里有前向依赖。修订后改为：正常路径只依赖已就绪的契约，尚未就绪的依赖先用恒放行的桩代替并注明替换的步骤；失败路径可以前向依赖，但要注明。
- **故障包与成熟度**（14.8、15.5）：故障包跑绿证明的是正确性，不再算作成熟度 L2；另用"故障包通过数"衡量构造进度。
- **intent 有、result 无的处置**（7.1、7.10、8.6）：四类处置在正文中写出并统一措辞：目标幂等→同 key 重试；可查询→查询后补记；可逆→补偿；都不行→标 unknown 交人工。
